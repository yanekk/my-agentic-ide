# Calendar agent wall: measurements

`claude --version`: 2.1.316. Measured 2026-11-01, macOS Darwin 25.5, agents on `--model haiku`.
Probes: `run.sh` (sections selected by `ONLY=` or `~/.wall-spike-scratch/only`); `clean.sh` removes them.
Refusals are read from files on disk or the tool results in the transcript, not from what the agent said.
Secrets were counted in bytes only.

"The wall" below is the §2.2 settings: sandbox block, deny rules, the guard hook, `--strict-mcp-config`, `dontAsk`.

## Also seen

- A worktree-isolated `--bg` session refuses a Bash line combining git with other commands, or `git -c …`: "names git in a form too complex to verify". Plain `git add`, `git commit` as single commands work.
- The sandbox's own write list: `/dev/{stdout,stderr,null,tty,dtracehelper,autofs_nowait}`, `/tmp/claude`, `/private/tmp/claude`, `~/.npm/_logs`, `~/.claude/debug`, `.`, `$TMPDIR`, the repo's `.git`.
- `.claude`, `skills`, `commands`, `agents`, `plugins`, `projects`, `jobs` under the home `.claude` refuse a shell write.
- Under `-p` the async Stop hook reports `outcome: cancelled`, exit 1, at process exit, so `-p` cannot show the ding; `--bg` was used for that.
- A job's state can stay `working` for 4 minutes after its last turn ended (review, `keyblock`, transcript shows `stop_hook_summary`), so a state wait alone is not a finish signal.
- Job state `blocked` here is the agent's own summary of a refusal, not a stall.

## Superfrog on the unlocked machine

The owner suggested the GPU failure came from a locked screen. Repeated with the machine unlocked (`frogwrite`, probe `smoke4`): `no GPU adapter … metal found no adapters` again, 19 lines, same e2e entries. So locking is not the cause. The same binary run outside the wall printed no error in a 30 s limit (its exit status was lost to a pipe, and a clean rerun was lost when the binary was deleted, so this control is weak). Smoke's result count in this run is not usable: the disk filled part way, `No space left on device`, failing later entries.

Disk cost: each superfrog worktree grew to about 5.8 GB of build output, four of them took the machine to 132 MB free. Their `target` folders were deleted at once (22 GB back). A real job's worktree stays until removed, so a nightly superfrog job costs about 5.8 GB per run until then.
